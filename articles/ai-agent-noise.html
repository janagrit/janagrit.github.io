Cutting through the AI agent noise: Hermes Agent, ECC, oh-my-claudecode and Arena compared

Iana Grytsenko · Updated October 18, 2026 · 10 min read

Everyone is talking about AI agents. Every week a new project goes viral on GitHub and promises to change how you work. It’s hard to tell what’s useful and what’s just noise.

Four names keep coming up: Hermes Agent, Everything Claude Code (ECC), oh-my-claudecode (OMC) and the Arena skill. People compare them as if you have to pick one. You don’t. They do completely different jobs. Here’s what each one is, in plain words.

01First, five words you’ll keep seeing

AI agent
An AI that doesn’t just answer. It takes actions: runs commands, edits files, sends messages, then checks the result and keeps going.
Claude Code
An AI agent for programming. It works inside your project, on your computer.
Skill
A saved set of instructions that teaches an agent one job, like a recipe card it can pull out when needed.
Sub-agent
A helper the main agent starts for one task. Like a manager handing work to a teammate.
Tokens
How AI usage is measured and billed. More work from the AI means more tokens, which means a bigger bill.

02Meet the four tools

Hermes Agent

A personal AI assistant that runs on its own.

You install it on your computer or a small cloud server, and it keeps working when your laptop is closed. You message it from Telegram, Slack, WhatsApp or Discord. It remembers you between conversations and can run tasks on a schedule. It works with many AI models, so you’re not tied to one company.

Think of it as: hiring an assistant who works from their own office and texts you updates.

ECC (Everything Claude Code)

An upgrade pack for an AI coding agent you already use.

It isn’t an agent by itself. It adds ready-made helpers, skills, rules and automatic checks to tools like Claude Code, Codex, Cursor and OpenCode. For example: a helper that plans before coding, one that reviews code, one that checks security, and one that makes the AI write tests first.

Think of it as: giving the assistant you already have a full training course and a professional toolkit.

oh-my-claudecode (OMC)

An add-on that runs Claude Code like a team.

Instead of one AI doing everything step by step, OMC splits a big task between several specialised agents, has them plan together, and keeps going until the result is checked, not just “looks done”. It also sends simple steps to cheaper AI models and hard ones to stronger models. You talk to it in plain words or with commands like /team and /execute.

Think of it as: a project manager who splits the work across a team and doesn’t sign off until it’s really finished.

Arena skill

One skill that makes many AIs compete for the best answer.

When Claude gives you a weak answer, you type /arena. It sends the same task to up to 100 helpers, and each one tries a different approach. They criticise each other’s answers in pairs, a judge scores each match, and the losers drop out round by round until one answer is left.

Think of it as: asking 100 people the same question, letting them debate, and keeping the answer that wins.

05Install only what you need

Every add-on you install loads its instructions into every Claude Code session, and those instructions cost tokens even when you don’t use them. So install only the tools the table above pointed you to.

The commands below go in your normal terminal, not inside Claude Code, so you can paste a whole block at once. (Inside Claude Code, /plugin commands must be typed one line at a time.)

ECC

Terminalclaude plugin marketplace add affaan-m/ECC claude plugin install ecc@ecc

oh-my-claudecode (OMC)

Terminalclaude plugin marketplace add Yeachan-Heo/oh-my-claudecode claude plugin install oh-my-claudecode@omc

Then open Claude Code and run /omc-setup once.

Arena

Terminalclaude plugin marketplace add Jakeschincariol/arena-skill claude plugin install arena-skill@arena-skill

Hermes Agent

Hermes isn’t a Claude Code add-on. It’s its own program, with its own installer. Read the script before you run it: piping a script from the internet into your shell runs it with your permissions.

Terminalcurl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

Can I install everything at once?

Yes. This block installs all three Claude Code add-ons in one go:

Terminal · all three add-onsclaude plugin marketplace add affaan-m/ECC claude plugin marketplace add Yeachan-Heo/oh-my-claudecode claude plugin marketplace add Jakeschincariol/arena-skill claude plugin install ecc@ecc claude plugin install oh-my-claudecode@omc claude plugin install arena-skill@arena-skill

But “can” isn’t “should”. All three together means hundreds of extra skills and agents loaded into every session, and two tools (ECC and OMC) that can both run long loops. Install everything only if you really use everything. Before keeping a plugin, check what it costs you:

Terminalclaude plugin details ecc@ecc

It lists everything the plugin adds and its projected token cost. If you stop using a tool, claude plugin disable switches it off without uninstalling it.

06Can I use them together?

Yes. ECC, OMC and Arena all plug into Claude Code, and they fit together: ECC decides how the work is done well, OMC decides who does it and in what order, and Arena settles the rare question that really matters. Hermes Agent is a separate program that runs next to them, for tasks that should happen without you.

One rule when you combine them: only one tool runs a long loop at a time. If OMC is pushing a task to the finish, don’t start another tool’s loop on the same task. My full ECC + OMC setup is in How I test with Claude Code.

I use ECC and OMC with Claude Code for my QA work, and Arena only for the rare hard question. An AI with every add-on loaded is like a test suite where every test is marked “critical”: when everything is important, nothing is.

07Example: a new project for example.com

Here’s how the two work together on a real kind of job. A company, example.com, asks you to set up automated tests for its website. You’ll use ECC for the everyday work and Arena for the one hard decision.

example.com is a placeholder name. On a real project, use the client’s site, and only test what they’ve allowed you to test.

Step 1. Install both, once

Type these inside Claude Code. You only do this the first time.

/plugin marketplace add affaan-m/ECC
/plugin install ecc@ecc
/plugin marketplace add Jakeschincariol/arena-skill
/plugin install arena-skill@arena-skill

Step 2. Create the project

In your terminal, make a folder for the project and start Claude Code in it.

mkdir example-com-tests
cd example-com-tests
git init
claude

Step 3. Let ECC pick what you need

ECC looks at your project and suggests which of its parts fit. It’s only a suggestion, so nothing changes until you agree.

/ecc:project-init

Step 4. Plan before any code

Ask for a plan. ECC writes it step by step and waits for your OK before it touches anything.

/ecc:plan Set up a Playwright + TypeScript test suite for example.com.
Start with the home page, the navigation and the contact form.

Step 5. Use Arena for the hard decision

Every project has one question that really matters. Here it’s “what do we test first?” Instead of trusting the first answer, let 16 helpers compete. --quick keeps the token bill small.

/arena-skill:arena --quick Which three user flows on example.com
should we automate first, and why? Rank them by business risk.

You get the winning answer, the criticism it survived and how many rounds it took. Feed that answer back into the plan.

Step 6. Build the tests

Ask Claude to write the tests with ECC’s testing skill, and to prove they’re stable.

Use the e2e-testing skill to write tests for the three flows we chose.
Run every test twice and tell me if any result changes.

Step 7. Review and check before you share

Ask ECC to review the code, then to run its full check: build, tests, security and a look over every change.

/ecc:code-review
/ecc:verification-loop

Fix what they find, commit, and send example.com a link with a short note on what the tests cover and what they caught.

08How I filter the noise

I test software for a living, so I treat a viral AI project like a new build: it’s not trusted until it’s tested. Before I install anything, I ask five questions:

  1. What is it? A whole agent, an add-on for an agent, or one skill?
  2. What problem does it solve for me? If I can’t say it in one sentence, I don’t need it yet.
  3. What can it touch? My files, my computer, my accounts, my messages?
  4. What does it cost to use? “Free” software can still mean a big AI bill.
  5. How will I know it helped? I try it on one real task and compare the result with and without it.

GitHub stars show that a project is popular. They don’t show that it solves your problem. Start with the problem, then pick the tool.
